---
title: Compatibility
description: The peer dependency versions, runtimes, and TypeScript settings Session kit supports and is tested with.
---

All peer dependencies are optional, so install only what you use:

| Peer                     | Range                   | Needed for                                             |
| ------------------------ | ----------------------- | ------------------------------------------------------ |
| `react`                  | `^18.0.0 \|\| ^19.0.0`  | `/react`, `/tanstack-router`, `/react-router`, `/expo` |
| `@tanstack/react-router` | `^1.132.0`              | `/tanstack-router`                                     |
| `@tanstack/react-start`  | `^1.169.0`              | `/tanstack-start/server`                               |
| `react-router`           | `^7.0.0 \|\| ^8.0.0`    | `/react-router`, `/react-router/server`                |
| `next`                   | `^16.0.0`               | `/next`                                                |
| `effect`                 | `^4.1.0`                | `/effect`                                              |
| `@monarcode/effetch`     | `^0.1.0-rc.2`           | `/effetch`                                             |
| `expo-router`            | `^5.0.2` through `^58`  | `/expo`                                                |
| `expo-secure-store`      | `^14.2.0` through `^58` | `/expo`                                                |
| `expo-file-system`       | `^18.1.0` through `^58` | `/expo`                                                |
| `react-native`           | `>=0.79.0`              | `/expo`                                                |

The Expo ranges cover Expo SDK 53 and newer; install them with
`npx expo install` so they match your SDK, as the
[Expo guide](/docs/setups/expo#installation) shows.
`/react-router/server` needs React Router's middleware: React Router 8, or
7.9 and later with `future.v8_middleware`.

CI tests the oldest and newest versions in each range, except that
`expo-file-system` is tested only at its newest: 18.1 publishes no `exports`
map, so its types don't resolve under NodeNext. Session kit never imports
React DOM.

The package is ESM-only and checked with TypeScript 6.0.3 under NodeNext and
Bundler resolution. It needs `AbortController`, and uses `crypto.randomUUID`
and Web Locks when present, falling back without them. On the server,
`@monarcode/session-kit/server` needs Web Crypto, as in Node.js 20 and newer.
